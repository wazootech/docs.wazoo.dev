## At a glance

|                | Linked Markdown (Wazoo)                                       | Vault-LD (The-Knowledge-Graph-Guys)                  |
| :------------- | :------------------------------------------------------------ | :--------------------------------------------------- |
| Core focus     | Formal W3C specification, multi-lang Extract API, & toolchain | Open specification & round-trip parser concept       |
| Frontmatter    | Standard JSON-LD / YAML-LD frontmatter                        | YAML-LD (JSON-LD serialized as YAML) with `@context` |
| Reference SDKs | PyPI (`linked-markdown`) & JSR (`@wazoo/linked-markdown`)     | Reference specification repo                         |
| Ecosystem      | Integrated with `wiki` CLI, Wazoo Worlds, and `memsdk`        | Standalone note vault specification                  |
| Publications   | Published W3C CG Editor's Draft & Zenodo DOI paper            | Open specification (`SPEC.md`)                       |

## The philosophical difference

**Linked Markdown (LMD)** (by Wazoo) and
**[Vault-LD](https://github.com/The-Knowledge-Graph-Guys/vault-ld)** (by The
Knowledge Graph Guys) are **virtually identical in data model and syntax**: both
embed machine-readable W3C Linked Data (RDF) inside human-readable Markdown
files via standard JSON-LD / YAML-LD frontmatter without introducing nonstandard
custom syntax.

The key difference is **toolchain maturity and real-world deployment**:

- **Linked Markdown (LMD)** is a complete, production-ready semantic
  infrastructure specification. It features an official W3C Community Group
  Editor's Draft, a published research paper (Zenodo DOI:
  `10.5281/zenodo.21216085`), high-performance multi-language Extract APIs
  (`linked-markdown-py` on PyPI, `@wazoo/linked-markdown` on JSR), and native
  integration across the Wazoo toolchain (`wiki` CLI, Wazoopedia, Worlds context
  engine, and `memsdk`).
- **Vault-LD** is primarily a conceptual specification (`SPEC.md`) focusing on
  lossless 1:1 round-tripping between Obsidian/desktop note vaults and RDF
  triplestores.

## Code comparison

Because both protocols standardize on JSON-LD frontmatter over CommonMark files,
the documents are virtually identical:

### Linked Markdown (LMD)

```markdown
---
{
  "@id": "https://wazoo.dev/team/gregory-davidson",
  "@type": "schema:Person",
  "@context":
    { "schema": "https://schema.org/", "wazoo": "https://schema.wazoo.dev/" },
  "schema:givenName": "Gregory",
  "schema:familyName": "Davidson",
  "wazoo:role": "Context Architect",
}
---

# Gregory Davidson

Gregory leads context engineering on Worlds.
```

### Vault-LD

```markdown
---
"@id": "https://wazoo.dev/team/gregory-davidson"
"@type": "Person"
"@context":
  "@vocab": "http://schema.org/"
  "wazoo": "https://schema.wazoo.dev/"
  "role":
    "@type": "@id"
name: "Gregory Davidson"
wazoo:role: "Context Architect"
---

# Gregory Davidson

Gregory leads context engineering on Worlds.
```

## Why choose Linked Markdown

- **Production-Ready SDKs**: Ready-to-install packages for Python
  (`pip install linked-markdown`) and TypeScript (`jsr:@wazoo/linked-markdown`)
  with deterministic `extract()` APIs that convert markdown directly to RDF
  quads and JSON-LD nodes.
- **W3C Community Draft & Academic Paper**: Backed by a formal W3C JSON-LD
  Community Group specification and a published DOI paper on semantic Markdown
  infrastructure.
- **End-to-End Toolchain**: Native integration with `wiki` CLI (linting, SHACL
  shape validation, SPARQL querying, and static site rendering) and Wazoo Worlds
  context engines.

## Interoperability

Because Linked Markdown and Vault-LD share the exact same underlying RDF 1.1
data model and JSON-LD semantics, they are **100% interoperable**. Any Vault-LD
document can be extracted, validated, and queried using `linked-markdown` SDKs
or the `wiki` CLI toolchain out of the box.
