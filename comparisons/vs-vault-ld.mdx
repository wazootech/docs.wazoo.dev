## At a glance

|              | Linked Markdown (Wazoo)                               | Vault-LD (The-Knowledge-Graph-Guys)                      |
| :----------- | :---------------------------------------------------- | :------------------------------------------------------- |
| Core focus   | Pragmatic Markdown-to-RDF spec & multi-lang SDKs      | Lossless round-trip specification (Markdown to/from RDF) |
| Frontmatter  | Standard JSON-LD frontmatter (or YAML equivalent)     | YAML-LD (JSON-LD serialized as YAML) with `@context`     |
| Syntax rules | Zero custom syntax; CommonMark + JSON-LD              | YAML-LD frontmatter & controlled vocabulary specs        |
| Ecosystem    | Integrated with `linked-markdown`, Wiki CLI, & Worlds | Standalone specification & reference parser              |
| Primary use  | Agent context, memory ledgers, and graph nodes        | Bi-directional RDF graph conversion for PKM notes        |

## The philosophical difference

Both **Linked Markdown (LMD)** (by Wazoo) and
**[Vault-LD](https://github.com/The-Knowledge-Graph-Guys/vault-ld)** (by The
Knowledge Graph Guys) address the exact same challenge: embedding
machine-readable W3C Linked Data (RDF) inside human-readable Markdown files
without introducing custom nonstandard markdown syntax.

In practice, **Linked Markdown and Vault-LD are almost identical in approach**:
both use JSON-LD / YAML-LD frontmatter blocks at the top of standard CommonMark
files so that a single `.md` document acts simultaneously as renderable prose
and a valid RDF graph node.

The subtle distinction lies in ecosystem goals:

- **Vault-LD** focuses heavily on **lossless bi-directional round-tripping**
  between Markdown files and RDF triplestores, maintaining strict YAML-LD
  frontmatter with explicit `@context` declarations.
- **Linked Markdown (LMD)** serves as the **foundational protocol for AI agent
  memory and context engines** (powering `linked-markdown-py`,
  `linked-markdown-ts`, Wiki CLI, and Wazoo Worlds).

## Code comparison

### Linked Markdown (LMD)

Linked Markdown defines JSON-LD frontmatter directly within standard `---`
delimiters:

```markdown
---
{
  "@id": "https://wazoo.dev/team/alice",
  "@type": "schema:Person",
  "@context":
    { "schema": "https://schema.org/", "wazoo": "https://wazoo.dev/ontology/" },
  "schema:givenName": "Alice",
  "schema:familyName": "Smith",
  "wazoo:role": "Context Architect",
}
---

# Alice Smith

Alice leads context engineering on Worlds.
```

### Vault-LD (The Knowledge Graph Guys)

Vault-LD uses YAML-LD (JSON-LD serialized as YAML) frontmatter with a shared
`@context`:

```markdown
---
"@id": "https://wazoo.dev/team/alice"
"@type": "Person"
"@context":
  "@vocab": "http://schema.org/"
  "wazoo": "https://wazoo.dev/ontology/"
  "role":
    "@type": "@id"
name: "Alice Smith"
wazoo:role: "Context Architect"
---

# Alice Smith

Alice leads context engineering on Worlds.
```

## When Linked Markdown fits

- You are building AI agent workflows, memory ledgers, or context engines.
- You want official Python (`linked-markdown`) and TypeScript
  (`@wazoo/linked-markdown`) packages for extracting quads and JSON-LD.
- You operate within the Wazoo ecosystem (`wiki` CLI, Worlds context engine).

## When Vault-LD fits

- You require formal, lossless bi-directional conversion where RDF graph updates
  write back into Markdown files without formatting loss.
- You are developing desktop note-taking extensions (Obsidian/Logseq) designed
  around formal Vault-LD spec compliance.

## Interoperability

Because both Linked Markdown and Vault-LD standardize on W3C JSON-LD frontmatter
and RDF 1.1 quads, they are **fully interoperable**. Any Vault-LD document is a
valid Linked Markdown document, and both can be parsed into RDF triplestores or
queried via SPARQL in Wazoo Worlds.
